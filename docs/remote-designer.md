# Удалённая работа с сервером 1С

Инструкция для пользователя: как подключить расширение к базе, которая обслуживается на сервере 1С.
Устройство (модель синхронизации, жизненный цикл подключения, протокол PowerShell-хоста, ограничения) —
в [architecture.md](./architecture.md#удалённый-сервер-1с).

## Что это даёт

Импорт из базы, загрузка в базу, обновление конфигурации и операции хранилища выполняются на сервере, а
не на вашей машине: файлы выгрузки передаются по SFTP (дельтой, а не целиком), хранилище читается
1cv8 на самом сервере.

Работают две независимые цепочки, и настраиваются они отдельно:

| Цепочка | Что делает | Транспорт | Настройки |
|---|---|---|---|
| Агент конфигуратора | импорт БД → проект, загрузка проект → БД, обновление БД | SSH + SFTP к агенту на сервере | `v8vscedit.agent.*` |
| Пакетный 1cv8 на сервере | операции хранилища (захват, помещение, получение, выгрузка, отчёт, метки, пользователи) | PowerShell-сессия (WinRM) | `v8vscedit.remote.*` |

Если хранилище не используется, достаточно первой цепочки.

## Требования

- Платформа 1С на сервере с поддержкой режима агента (локальный пилот — 8.3.27.2130 на файловой базе;
  серверная цепочка проверяется по чек-листу раздела 8).
- Клиент-серверная база в `--ibconnection` из `env.json` (`/S<сервер>\<база>`) — см. раздел «Что работает
  удалённо, а что локально».
- Для хранилища: на сервере включён WinRM (PowerShell Remoting), на вашей машине — Windows PowerShell 5.1
  (`powershell.exe`), учётная запись Windows с правом входа в WinRM-сессию сервера.
- Сетевой доступ с вашей машины к порту агента (по умолчанию 1543) и, для хранилища, к порту WinRM
  (5985 HTTP / 5986 HTTPS).

## 1. Запуск агента на сервере

Агент запускается на сервере вне расширения — вручную, службой или задачей планировщика. Запускать из
PowerShell или `cmd`, а не из Git Bash: MSYS переписывает аргументы `/AgentMode` как POSIX-пути.

Строка запуска со стенда пилота (сервер 1С, клиент-серверная база). Команда записана **одной строкой**:
её можно вставить и в `cmd`/`.bat`/ярлык/задачу планировщика, и в PowerShell (в PowerShell — с оператором
вызова `&` перед путём в кавычках).

```bat
"C:\Program Files\1cv8\common\1cestart.exe" DESIGNER /S "server\base" /N "Login" /P "Password" /AgentMode /AgentBaseDir "C:\AgentBaseDir" /AgentSSHHostKeyAuto /AgentSSHHost 127.0.0.1 /AgentSSHPort 1543 /Visible /AgentListenAddress 0.0.0.0
```

Не разбивайте команду на строки обратной кавычкой `` ` ``: это перенос только для PowerShell. В `cmd`,
`.bat` и ярлыке выполнится лишь первая строка. 1cv8 стартует без хвоста ключей и, если потерялся
`/AgentSSHHostKeyAuto`, падает с ошибкой «Фатальная ошибка SSH-сервера: ECDSA, ED25519, DSA, or RSA host
key file must be set» (см. раздел 6).

| Ключ | Назначение |
|---|---|
| `1cestart.exe` | стартер платформы: сам выбирает установленную версию 1cv8; вместо него можно указать конкретный `C:\Program Files\1cv8\<версия>\bin\1cv8.exe`. Это касается только запуска самого агента: в `v8vscedit.remote.v8Path` и для пакетных операций стартер недопустим (раздел 2) |
| `/S`, `/N`, `/P` | база (`сервер\база`) и пользователь ИБ; тем же логином и паролем расширение входит в агента |
| `/AgentMode` | включает режим агента конфигуратора |
| `/AgentBaseDir` | каталог данных агента: в нём создаются персональные каталоги пользователей и индекс `agentbasedir.json`. Каталог должен существовать, и у пользователя, от которого запущен 1cv8, должно быть право на запись. Расширению путь не нужен — корень SFTP уже персональный |
| `/AgentSSHHostKeyAuto` | агент сам создаёт ключ хоста SSH; без него нужен `/AgentSSHHostKey <файл ключа>` |
| `/AgentSSHPort` | порт SSH-сервера агента; должен совпадать с `v8vscedit.agent.port`. Локальный агент расширение запускает ключом `/AgentPort`; 1543 — порт по умолчанию |
| `/AgentListenAddress` | адрес прослушивания; для доступа с другой машины — `0.0.0.0` или адрес сетевого интерфейса сервера |
| `/AgentSSHHost` | в строке стенда задан `127.0.0.1` одновременно с `/AgentListenAddress 0.0.0.0`. Какой из ключей определяет адрес прослушивания, не установлено. Если с вашей машины `Connection refused`, проверьте адрес прослушивания (раздел 6) и при необходимости уберите `/AgentSSHHost 127.0.0.1` |
| `/Visible` | окно конфигуратора видно на сервере: удобно на пилоте, чтобы видеть диалоги ошибок; для службы не нужен |

Откройте порт агента на брандмауэре сервера. Вход в агента — логином и паролем пользователя
информационной базы (тот же логин/пароль, что в `env.json`/SecretStorage), либо ключом, если задан
`v8vscedit.agent.privateKeyPath`.

Ключ хоста SSH расширением сейчас НЕ проверяется (известное ограничение, закрывается до слияния ветки
в `main`): подключайтесь только по доверенной сети. Какой ключ агент хранит между перезапусками
(`/AgentSSHHostKeyAuto` или `/AgentSSHHostKey`) — на вашем стенде не проверено.

## 2. Настройки расширения

Настройки — в `settings.json` проекта или пользователя. Пароли в настройки не пишутся.

### Режим и адрес агента

```jsonc
{
  "v8vscedit.configuration.operationMode": "agent",
  "v8vscedit.agent.location": "remote",
  "v8vscedit.agent.host": "srv-1c.example.com",
  "v8vscedit.agent.port": 1543,
  "v8vscedit.agent.user": ""   // пусто — --db-user из env.json
}
```

Режим `batch` вместе с `location = remote` не поддерживается: расширение выдаст явную ошибку
конфигурации, а не запустит операцию локально.

| Настройка | По умолчанию | Смысл |
|---|---|---|
| `v8vscedit.configuration.operationMode` | `batch` | для удалённого режима обязательно `agent` |
| `v8vscedit.agent.location` | `local` | `remote` — агент уже запущен на сервере; `autoStart` игнорируется |
| `v8vscedit.agent.host` | `localhost` | адрес SSH-сервера агента |
| `v8vscedit.agent.port` | `1543` | порт агента |
| `v8vscedit.agent.user` | пусто | логин SSH; пусто — `--db-user` из `env.json` |
| `v8vscedit.agent.privateKeyPath` | пусто | приватный SSH-ключ вместо пароля |
| `v8vscedit.agent.transferConcurrency` | `16` | сколько файлов передаётся параллельно (запросов SFTP); больше — быстрее на канале с большой задержкой, но выше нагрузка на сервер |
| `v8vscedit.agent.archiveThresholdFiles` | `20000` | только удалённый агент: начиная с какого числа изменённых файлов импорт идёт полной выгрузкой архивом, а не по одному файлу. Если в settings.json когда-то задано прежнее `300`, оно сохраняется (миграции нет) — уберите строку или поднимите значение, иначе массовые правки по-прежнему будут уходить архивом |
| `v8vscedit.agent.idleDisconnectMinutes` | `0` | через сколько минут простоя агент сам отключает информационную базу; `0` — не отключать по таймеру |
| `v8vscedit.agent.authWarmupMs` | `90000` | окно повтора ошибок входа сразу после старта агента (агент открывает порт раньше, чем принимает логин) |
| `v8vscedit.agent.startupTimeoutMs` | `15000` | сколько ждать открытия порта и повторять «порт закрыт»/«нет ответа» |
| `v8vscedit.agent.connectTimeoutMs` | `60000` | предел одной попытки SSH-подключения: TCP, обмен ключами и вход вместе. Удалённый агент проверяет пароль обращением к базе, и на стенде пилота вход занимал больше 10 с (обмен ключами — 0,7 с) |

Остальные `v8vscedit.agent.*` (`autoStart`, `visible`, `agentModeArgs`, `listenAddress`, `progressInterval`)
относятся к локальному агенту, который запускает само расширение.

Пароль входа в агента — пароль информационной базы: он берётся из SecretStorage VS Code (как для
обычных операций с базой) и в файлах проекта не хранится.

### PowerShell-сессия (для хранилища)

```jsonc
{
  "v8vscedit.remote.user": "DOMAIN\\ivanov",
  "v8vscedit.remote.authentication": "Negotiate"
}
```

| Настройка | По умолчанию | Смысл |
|---|---|---|
| `v8vscedit.remote.user` | пусто | учётная запись Windows для PSSession (`DOMAIN\user`). Обязательна: без неё операция хранилища откажет |
| `v8vscedit.remote.computerName` | пусто | имя сервера для WinRM; пусто — `v8vscedit.agent.host` |
| `v8vscedit.remote.authentication` | `Default` | `Default` / `Negotiate` / `Kerberos` (`-Authentication` у `New-PSSession`); `Kerberos` требует доменного сервера и DNS-имени вместо IP |
| `v8vscedit.remote.useSsl` | `false` | WinRM по HTTPS |
| `v8vscedit.remote.port` | `0` | порт WinRM; `0` — стандартный (5985 / 5986 с SSL) |
| `v8vscedit.remote.v8Path` | пусто | путь к `1cv8.exe` НА СЕРВЕРЕ — только `…incv8.exe` конкретной версии, НЕ стартер `commoncestart.exe`; пусто — выводится из `--v8version` в `env.json` (стандартный каталог платформы) и проверяется на сервере |
| `v8vscedit.remote.ibConnection` | пусто | строка подключения к базе С ТОЧКИ ЗРЕНИЯ СЕРВЕРА (например `/Ssrv/base`), если из сервера кластер адресуется иначе, чем в `--ibconnection` |

**Почему не `1cestart.exe`.** Стартер запускает настоящий `1cv8` и сразу завершается: пакетная операция
«заканчивается» раньше реального конца, расширение идёт дальше, а база ещё занята — следующий `connect-ib`
агента падает на блокировке. Поэтому стартер отвергается ДО запуска (локальный путь, поиск через `PATH`,
`remote.v8Path`, ответ хоста PowerShell), сообщение: «… указывает на стартер 1cestart.exe …»; «Проверить
подключение к серверу 1С» показывает в части 1cv8 причину `v8-starter`. Проверка — по имени файла;
на сервере допустим только `1cv8.exe` (тонкий клиент `1cv8c.exe` тоже отвергается при запуске операции, но
«Проверить подключение» ловит только стартер).

Смена любой настройки `v8vscedit.agent.*` или `v8vscedit.remote.*` пересоздаёт подключения; если в этот
момент идёт операция с конфигурацией, сброс откладывается до её завершения.

## 3. Пароли

| Пароль | Где хранится | Как задать и сбросить |
|---|---|---|
| Пароль входа в агента (= пароль информационной базы) | SecretStorage VS Code, как для обычных операций | как для обычной работы с базой |
| Пароль PowerShell-сессии (`v8vscedit.remote.user`) | SecretStorage, отдельный ключ `remote-` | запрашивается при первой удалённой операции хранилища и сохраняется только после успешного входа; сброс — команда «Сбросить пароль удалённого сервера» |
| Пароль хранилища конфигурации | как и раньше | диалоги хранилища |

Если сервер отклонил пароль PowerShell-сессии, расширение стирает сохранённый пароль и НЕ повторяет вход
автоматически (повторы заблокировали бы учётную запись по политике домена): следующая операция спросит
пароль заново. Если пароль в домене сменили, а вход «молча» не удаётся, выполните
«Сбросить пароль удалённого сервера».

## 4. Команды

Все три — в палитре команд (Ctrl+Shift+P).

**«Проверить подключение к серверу 1С»** (`v8vscedit.remote.checkConnection`). Работает только при
`location = remote`. Одна попытка на каждую часть, без ожидания прогрева. Результат — в канале «1С Редактор»
(строки `[remote-check]`: `[OK]` / `[ОШИБКА]` / `[ПРОПУЩЕНО]`) и в уведомлении (при ошибке — причина первой
неудавшейся части):

1. **SSH** — вход в агента под нужным пользователем.
2. **Информационная база** — `connect-ib`/`disconnect-ib`; если база уже подключена агентом, подключение не
   трогается.
3. **SFTP** — запись, чтение и удаление пробного файла в каталоге обмена.
4. **PowerShell** — открытие сессии и запись во временный каталог сервера (`%TEMP%\v8vscedit-*`).
5. **1cv8** — найден ли `1cv8.exe` на сервере (по `v8Path` или по версии платформы) и не стартер ли это
   (`1cestart.exe` — отказ с причиной `v8-starter`).

PowerShell проверяется независимо от исхода SSH: это другой транспорт и другая учётная запись. Команда берёт
общий замок операций с конфигурацией и не запустится поверх идущей операции.

**«Агент конфигуратора: отключить информационную базу»** (`v8vscedit.agent.releaseInfoBase`). Агент держит
подключение к базе между операциями (так цикл «загрузить → обновить базу → загрузить» не переподключается
каждый раз), и это подключение занимает базу для коллег и интерактивного Конфигуратора. Команда отпускает
базу явно. Автоматически база отпускается перед пакетной операцией Конфигуратора (хранилище) и интерактивным
Конфигуратором (CF/CFE, пакеты расширений и список расширений идут через самого агента и базу не отпускают); по таймеру — если задан
`v8vscedit.agent.idleDisconnectMinutes`. После команды следующая операция подключит базу снова сама.

**Первый импорт: диалог «Использовать выгрузку проекта».** Когда зеркало выгрузки на сервере ещё не создано
(первый импорт цели) и в проекте есть пригодная выгрузка с `ConfigDumpInfo.xml` (тот же вид и имя
конфигурации, иерархический формат известной версии), расширение спрашивает, чем засеять зеркало:

- **«Использовать выгрузку проекта»** — серверная выгрузка не нужна, скачиваются только объекты,
  изменённые в базе после файла версий проекта. Быстро, но ручные правки XML в проекте после той выгрузки,
  не загруженные в базу, перезаписаны НЕ будут: они войдут в базовую линию, не попадут в загрузку «по
  изменениям», и расхождение проекта и базы останется до полной загрузки.
- **«Полная выгрузка»** — одна серверная выгрузка архивом; надёжнее, но для большой конфигурации
  заметно дольше.
- Закрытие диалога — отмена операции.

Нет пригодной выгрузки в проекте — диалога нет, идёт полная выгрузка. Из MCP-инструментов импорт всегда
идёт как «Полная выгрузка»: параметра согласия на посев у них намеренно нет — скрытое расхождение
проекта и базы должен принимать человек, а не агент.

**Удаление и переименование объектов.** Для основной конфигурации они больше не дают полную выгрузку.
Платформа в таком случае сообщает `FullDump`; расширение получает свежий `ConfigDumpInfo.xml` базы
(отдельная быстрая операция, архив конфигурации не скачивается), находит пропавшие объекты, убирает их из
зеркала на сервере и дальше работает обычной дельтой: скачиваются только изменённые объекты, файлы
удалённых и переименованных (старое имя) объектов удаляются из `src/cf`. Так же обрабатывается удаление
формы у живого объекта: объект целиком перевыгружается, лишние файлы формы удаляются. Вопросов при этом
нет. Для расширений (`src/cfe/<имя>`) прежний путь: удаление или переименование — полная выгрузка.

Если очистка зеркала невозможна (например, в базе удалена часть корня конфигурации или свежий файл версий
получить не удалось), расширение спрашивает **«Перезаписать зеркало на сервере»**: сервер перегенерирует
выгрузку у себя (это долго на больших конфигурациях), но скачиваются только изменённые файлы. Отказ
(или закрытие диалога) отменяет операцию, проект не меняется. Из MCP-инструментов вопроса нет.

**Вопрос перед полной выгрузкой.** (Задаётся и на пути загрузки — до очистки зеркала; отказ даёт «Загрузка отменена; база и проект не изменены».) Полная серверная выгрузка нужна, когда без неё нельзя: в базе удалены или
переименованы объекты РАСШИРЕНИЯ (платформа сообщает это как `FullDump`; для основной конфигурации см. выше), список изменений не распознан, объекты не
удалось сопоставить файлам, изменено больше файлов, чем `archiveThresholdFiles`, либо зеркало на сервере
пусто и посев из проекта невозможен. Перед ней расширение спрашивает:

- **«Полная выгрузка на сервере»** — одна выгрузка архивом.
- **«Выгружу вручную»** (или закрытие диалога) — операция отменяется, проект не меняется. Выгрузите
  конфигурацию на сервере Конфигуратором («Выгрузить конфигурацию в файлы», иерархический формат, ТА ЖЕ
  версия платформы), очистите `src/cf` (или каталог расширения) и скопируйте выгрузку целиком, включая
  `ConfigDumpInfo.xml` (без очистки файлы удалённых объектов останутся). Следующий импорт распознает замену и
  предложит посев из неё.

Из MCP-инструментов вопроса нет: полная выгрузка выполняется без него.

**Ручная замена выгрузки проекта.** Расширение запоминает отпечаток `ConfigDumpInfo.xml` проекта после
каждого успешного импорта. Если при следующем импорте он изменился, выгрузка считается заменённой извне и
задаётся тот же вопрос о посеве, что и при первом импорте. Компромисс: подмена файла с тем же размером и
тем же временем изменения не распознаётся.

**Файлы без объектов («сироты»).** После посева из проекта расширение ищет в выгрузке файлы объектов,
которых нет в `ConfigDumpInfo.xml` проекта (объект удалён до ручной выгрузки поверх прежней) и которые не
входят в список изменений. Файлы удаляются только по подтверждению («Удалить файлы», Esc — оставить; из MCP
не удаляются — только сообщение в журнале). Ограничения: ищутся лишь объекты верхнего уровня (сироты уровня
подобъектов не ищутся); локально созданный и ещё не загруженный в базу объект тоже попадёт в список —
«нет в базе» здесь фактически означает «нет в `ConfigDumpInfo.xml` проекта», поэтому не подтверждайте
удаление, не убедившись, что среди объектов нет ваших новых.

**Точечное восстановление.** Если вы правили локально файлы объекта, который в базе не менялся, импорт не
делает полную выгрузку: нужные файлы выгружаются из базы точечно (`dump --list-file`) во временный каталог
обмена и откатывают правки; зеркало на сервере не меняется. Полная выгрузка (с вопросом) остаётся
запасным путём, если точечная не удалась.

**Прогресс и отмена импорта.** Импорт показывает уведомление с текущим этапом и кнопкой **«Отмена»**; те же
строки идут в канал «1С Редактор». Счётчики: «Просмотр зеркала: объектов N из M», «Проверка файлов зеркала:
N из M», «Скачивание изменённых файлов: N из M (P%), X МБ», «Запись в проект: N из M файлов». В журнал
счётчик попадает каждые 10 % и не реже раза в 15 с, в уведомление — не чаще двух раз в секунду; длинный
шаг без счётчика (обновление зеркала на сервере командой агента) даёт одну строку на входе. Перед каждым
вопросом (посев, полная выгрузка, сироты, запрос агента) в журнале «Ожидание ответа пользователя: …», после —
«Ответ пользователя: …»; ответ на запрос пароля в журнал не пишется. Строка «Изменено в зеркале: X из Y
файлов изменённых объектов» говорит, сколько файлов скачивается (остальные платформа не переписывала).

Скачивание считается по весу, а не по числу файлов: «Скачивание изменённых файлов: 27 из 28, 312,4 МБ из 1,19 ГБ
(25%), 5,8 МБ/с, осталось ~3 мин 31 с». До начала в журнале: «Скачивается N файлов, X ГБ»; если среди них есть
файл от 100 МБ — «Среди скачиваемых — файл 1,18 ГБ: <путь>» (так видно, почему операция долгая), а перед самим
большим файлом — «Скачивание большого файла (…)». Большие файлы (от 16 МиБ) идут потоком на диск и сравниваются с
проектом без загрузки в память; если на диске не хватает места, операция остановится до скачивания с сообщением
«Недостаточно места на диске…».

**Конфигурация поставщика больше не перекачивается.** Файлы `Ext/ParentConfigurations/*.cf` (конфигурация
поставщика, на БП КОРП — больше гигабайта) расширению не нужны, а платформа переписывает их при любой правке корня
конфигурации. Раньше после получения из хранилища импорт качал такой файл около часа. Теперь он скачивается только
если список изменений агента называет часть `ParentConfigurations`, либо изменился `ParentConfigurations.bin`
(версия поставщика), либо файла нет в проекте или его размер другой. Если файл пропущен, в журнале:
«Конфигурация поставщика не изменилась (по списку изменений агента): пропущено файлов — N, размер…». Если
`.bin` изменился, а список изменений часть не назвал, журнал сообщает об этом, и файлы поставщика скачиваются.
Ограничение: локальная правка `.cf` проекта, не меняющая размер файла, не обнаруживается (файл создаёт платформа).
Скорость скачивания на стенде упирается в канал (~300 КБ/с), а не в протокол агента.

Цена кнопки «Отмена»: операция остановится в ближайшей безопасной точке. Команда агента, которая уже
выполняется на сервере, не прерывается — она доходит до конца, потом операция останавливается, и база
отключается от агента (следующая операция подключит её заново за секунды). Проект записывается только после
полного скачивания, поэтому наполовину обновлённым он не бывает. Если отмена пришла ПОСЛЕ того, как зеркало на
сервере уже обновлено, журнал предупредит: «Импорт прерван после изменения зеркала агента…» — следующий импорт
заново подготовит зеркало (посев из выгрузки проекта или полная выгрузка), то есть будет дольше обычного. У
загрузки в базу и обновления БД кнопки «Отмена» нет.

**Получение из хранилища** (`v8vscedit.repository.update`) работает так же, как захват ниже: если
получение изменило базу (в логе есть «Объект получен из хранилища» или «Объект удален из конфигурации»),
изменённые объекты сразу импортируются в проект. При незагруженных правках проекта до получения задаётся
вопрос: «Получить, затем загрузить правки в базу» / «Получить, проект не обновлять» / отмена. Правки
загружаются ПОСЛЕ получения: платформа при получении возвращает к версии хранилища и захваченные вами
объекты (с `-force` и без), поэтому загруженное до получения было бы потеряно. Если в получаемую выборку
попадают захваченные вами объекты, расширение заранее покажет их список и спросит подтверждение: правки этих
объектов, загруженные в базу и не помещённые в хранилище, получение сбросит. Удалённый в хранилище объект
платформа удаляет из базы и без `-force`; импорт уберёт его файлы из проекта.

**Захват объектов хранилища** (`v8vscedit.repository.lock`, в `remote` — удалённым исполнителем). Захват
сам по себе файлы проекта не меняет, но платформа при захвате ПОЛУЧАЕТ в базу новые версии объектов,
изменённые в хранилище коллегами (лог: «Объект получен из хранилища: …»; это происходит и без ключа
`-revised` — проверено на 8.3.27.2130). Чтобы проект не отставал от базы, расширение в той же секции замка
операций делает импорт изменившихся объектов в проект:

- настройка `v8vscedit.repository.getRevisedOnLock` (по умолчанию `true`) управляет ТОЛЬКО ключом
  `-revised` (захват с получением версий захватываемых объектов). Импорт от неё не зависит: он нужен всякий
  раз, когда лог захвата содержит «Объект получен из хранилища»;
- лог без таких строк — импорта нет; лог не распознан — импорт делается консервативно (лишний импорт лучше
  проекта, отстающего от базы);
- если в проекте есть правки, не загруженные в базу, ДО захвата задаётся вопрос: **«Загрузить правки в
  базу, затем захватить»** (правки должны относиться к уже захваченным объектам — незахваченный платформа
  загрузить не даст), **«Захватить, проект не обновлять»** (база получит новые версии, файлы проекта
  останутся прежними; расширение предупредит, что перед «Обновить БД» нужен «Импорт конфигурации») или
  отмена. Молчаливой потери правок нет: в подключённой к хранилищу базе загрузка незахваченного объекта
  отклоняется платформой;
- тост «Объекты захвачены» показывается всегда; вопросы импорта (посев, полная выгрузка, сироты) задаются
  внутри той же секции;
- если импорт после захвата не удался, отметки захвата сохраняются, а расширение предупреждает: выполните
  «Импорт конфигурации» до любой загрузки в базу, иначе загрузка перезапишет полученные версии.

**MCP-операции хранилища** (`v8vscedit_repository_status|lock|update|commit|unlock`) идут тем же исполнителем
(local/remote по `v8vscedit.agent.location`), что и команды интерфейса, и теми же цепочками: пароль хранилища
берётся из SecretStorage, агент его не передаёт. Вопросы, которые интерфейс задаёт диалогом, MCP-клиент
указывает параметрами; окна согласия импорта (полная выгрузка, посев, сироты) всё равно показываются вам, а
MCP-вызов ждёт ответа. Подробности — [architecture.md](./architecture.md#операции-хранилища-как-mcp-инструменты).

**«Сбросить пароль удалённого сервера»** (`v8vscedit.remote.resetPassword`). Стирает пароль PowerShell-сессии из
SecretStorage и закрывает хост PowerShell проекта; пароль будет запрошен при следующей операции хранилища.

## 5. Что работает удалённо, а что локально

| Операция | Где выполняется при `location = remote` |
|---|---|
| Импорт, загрузка и обновление БД из исходников (в т. ч. из MCP-инструментов) | на сервере через агента, файлы — по SFTP |
| Операции хранилища (захват, помещение, получение, выгрузка, отчёт, метки, пользователи, привязка) | на сервере: 1cv8 запускается через PowerShell-сессию |
| Импорт: зеркало на сервере после первого импорта — РАЗРЕЖЕННОЕ (файл версий, `Configuration.xml` и файлы изменённых объектов), не полная копия выгрузки; это нормально и экономит место и время | на сервере |
| Загрузка и выгрузка CF/CFE-файлов, пакеты «все расширения», список расширений (в т. ч. для «Подключить расширение»), MCP `load_cf`/`dump_cf`/`load_all_cfe`/`dump_all_cfe`/`update_database_configuration` в режиме `operationMode = agent` | на сервере через агента, файлы по SFTP потоком (файловая база на сервере тоже работает) |
| Интерактивный Конфигуратор, режим `batch`, CLI | ЛОКАЛЬНЫЙ 1cv8 на вашей машине (см. ниже) |
| Запуск 1С:Предприятие (тонкий клиент) | как и раньше |

Для операций, которые остались локальными (интерактивный Конфигуратор, batch, CLI), вид базы в `--ibconnection` из `env.json` определяет, можно ли их выполнить:

| Вид `--ibconnection` | Результат |
|---|---|
| клиент-серверная (`/S`, `Srvr=`) с сетевым именем сервера | выполняется локальным 1cv8 по сети (та же база, но медленнее); в журнал пишется одна строка |
| файловая (`/F`, `File=`) | отказ до побочных эффектов: путь указан для сервера, локальный 1cv8 его не видит или откроет другую базу |
| клиент-серверная с петлевым адресом сервера (`localhost`, `127.x.x.x`, `.`, `::1`) | отказ: строка записана с точки зрения сервера, локальный 1cv8 ушёл бы в кластер на вашей машине |
| `env.json` нет | операция сама сообщит о проблеме подключения |

Выход из отказа: указать в `--ibconnection` сетевое имя сервера или вернуть `v8vscedit.agent.location = "local"`.
Для хранилища строка подключения «с точки зрения сервера» может быть переопределена `v8vscedit.remote.ibConnection`.

## 6. Типовые ошибки

| Сообщение / симптом | Причина и что делать |
|---|---|
| Окно на сервере при запуске агента: «Фатальная ошибка SSH-сервера: ECDSA, ED25519, DSA, or RSA host key file must be set» | 1cv8 не получил `/AgentSSHHostKeyAuto` (или `/AgentSSHHostKey`). Почти всегда это обрыв команды: многострочная PowerShell-команда с `` ` `` вставлена в `cmd`/`.bat`/ярлык, и выполнилась только первая строка. Запустите одной строкой (раздел 1). Если ключ точно передан — проверьте, что каталог `/AgentBaseDir` существует и доступен на запись пользователю, от которого запущен 1cv8 |
| `ssh: connect to host … port 1543: Connection refused` | сервер доступен, но на этом адресе и порту никто не слушает: агент не запущен или упал (смотрите окна ошибок на сервере), слушает только петлю `127.0.0.1` (потерян `/AgentListenAddress 0.0.0.0`, см. также `/AgentSSHHost` в разделе 1) или порт другой. На сервере: `Get-NetTCPConnection -LocalPort 1543 -State Listen` — какой `LocalAddress`. На своей машине: `Test-NetConnection <сервер> -Port 1543`, `ssh -4 -p 1543 <пользователь>@<сервер>` — если `-4` подключается, а без него нет, имя резолвится в IPv6; укажите в `v8vscedit.agent.host` IPv4-адрес. Молчаливая блокировка брандмауэром выглядит иначе — «Connection timed out» |
| «неверный логин или пароль агента конфигуратора для пользователя …» | вход отклонён вне окна прогрева агента: проверьте логин (`agent.user`/`--db-user`) и пароль ИБ в SecretStorage. Повторов нет намеренно — серия неудачных входов может заблокировать пользователя 1С |
| «Permission denied» сразу после старта агента на сервере | агент открывает порт раньше, чем принимает логин; расширение повторяет вход только в окне `agent.authWarmupMs` после наблюдённого «порт закрыт». Подождите и повторите; при постоянном отказе — тот же пункт про пароль |
| «агент конфигуратора не отвечает на host:port» | агент не запущен, порт закрыт брандмауэром или неверен `agent.host`/`agent.port`; для постоянно медленного старта увеличьте `agent.startupTimeoutMs` |
| «не ответил вовремя (Timed out while waiting for handshake)» | подключение вместе со входом не уложилось в `agent.connectTimeoutMs`. Название из библиотеки ssh2 вводит в заблуждение: таймер охватывает и вход, а не только обмен ключами. Если `ssh -p <порт> <пользователь>@<сервер>` из терминала подключается, но долго — увеличьте `agent.connectTimeoutMs` |
| «Unable to start subsystem: sftp» / «нет подсистемы SFTP» | агент не отдаёт SFTP; проверка подключения покажет это в части SFTP. Версия платформы должна поддерживать SFTP в режиме агента |
| SFTP: «не удалось записать пробный файл» | нет прав на запись в персональный каталог агента или каталог `/AgentBaseDir` недоступен для записи |
| «Array buffer allocation failed» при первом импорте большой конфигурации | ошибка старых версий расширения (архив читался в память целиком); исправлена потоковой схемой. Если встретилась — обновите расширение |
| «Полная выгрузка на сервере отменена. Выгрузите конфигурацию в файлы вручную…» | вы выбрали «Выгружу вручную» (или закрыли диалог): проект не изменён. Выполните ручную выгрузку по инструкции из раздела 4 либо повторите импорт и выберите «Полная выгрузка на сервере» |
| «Разреженное зеркало агента не содержит файлов, нужных импорту: …» | зеркало на сервере разрежено (посев), а нужные файлы в нём пропали (очищено на сервере). Повторите импорт; при повторении удалите манифест цели из `.v8vscedit/agent-sync/` — следующий импорт станет полным архивным |
| «Не удалось отключить информационную базу от агента конфигуратора» | пакетная операция не стартует, пока база подключена: смотрите причину в журнале, затем повторите или выполните «отключить информационную базу» |
| «Для удалённого Конфигуратора не задана учётная запись PowerShell-сессии» | заполните `v8vscedit.remote.user` |
| «Сервер … отклонил учётные данные … для PowerShell-сессии» | пароль неверен; сохранённый пароль уже удалён, следующая операция спросит новый. Для Kerberos используйте DNS-имя сервера, не IP |
| «На сервере … не найден 1cv8» / «не найдена платформа 1С версии …» | задайте `v8vscedit.remote.v8Path` (путь НА СЕРВЕРЕ) или проверьте `--v8version` в `env.json` |
| «… указывает на стартер 1cestart.exe …» / в проверке подключения причина `v8-starter` | `v8Path` (или найденный в `PATH`/по версии файл) — стартер платформы. Укажите `…incv8.exe` конкретной версии (на сервере: `C:\Program Filescv8\<версия>incv8.exe`) |
| «Информационная база занята другим Конфигуратором… в течение 15 с» / «Ошибка блокировки информационной базы для конфигурирования» (`error-type: DesignerAlreadyStarted`) | агент не смог подключить базу: её держит другой Конфигуратор. Расширение повторяет `connect-ib` 15 с (0,5 → 1 → 2 с, в журнале «База занята… повторяю»). Причины: открыт интерактивный Конфигуратор этой базы; в `v8Path` стартер вместо 1cv8 (пакетная операция «завершилась» раньше времени); пакетная операция ещё не завершилась; другое окно VS Code или CLI. Закройте держателя и повторите. На клиент-серверной базе окно 15 с не замерено — при частых отказах сообщите |
| импорт долго «ничего не пишет» / кажется, что завис | смотрите последнюю строку в канале «1С Редактор» и уведомление: «Обновление зеркала агента на сервере…» — работает команда агента на сервере (на большой базе минуты, строк до её конца не будет); «Просмотр/Проверка/Скачивание … N из M» — идёт счётчик, строка обновляется не реже раза в 15 с; «Ожидание ответа пользователя: …» — ждёт ваш ответ в диалоге (он может быть скрыт за окном). Если строк нет дольше минуты вне команды агента — «Отмена» в уведомлении; после отмены на шаге изменённого зеркала следующий импорт будет дольше (см. раздел 4) |
| «Загрузка отменена; база и проект не изменены…» | на вопрос о полной выгрузке (до очистки зеркала на загрузке) выбрано «Выгружу вручную» или диалог закрыт |
| после посева отказ «…зеркало уже обновлено…» | отмена в фазе 2 после посева: зеркало на сервере уже обновлено, проект и база — нет; текст отличается от отказа при импорте и при загрузке — повторите операцию |
| «Удалённый агент … работает только в агентском режиме» | при `location = remote` нужен `v8vscedit.configuration.operationMode = "agent"` |
| «Удалённый режим агента … с файловой базой …» | см. раздел 5: локальным операциям нужна клиент-серверная база с сетевым именем сервера |
| «Не удалось прочитать индекс пользователей агента конфигуратора…» | относится к ЛОКАЛЬНОМУ внешнему агенту: укажите его `/AgentBaseDir` в `v8vscedit.agent.agentModeArgs`. Для удалённого агента индекс не нужен |
| «Расширение «X» загружено, но не применено: …» (E7) | `load-cfg` нового расширения прошёл, `update-db-cfg` нет: вероятно, внутреннее имя в файле совпадает с другим расширением базы. В базе осталась неприменённая заглушка «X» - удалите её в Конфигураторе |
| «Расширение «X» в базе не применено (неприменённая заглушка от прерванной загрузки): выгружать нельзя…» (E3) | выгрузка заглушки (`hash-sum` из нулей) роняет агента, поэтому команда не отправляется. Загрузите расширение заново или удалите его в Конфигураторе |
| «Расширения «X» нет в базе. Расширения базы: …» (E5) | имя не найдено в списке расширений; регистр не важен, проверьте имя по перечню в сообщении |
| «Агент сообщил об успешной выгрузке, но файл на сервере не создан или пуст: …» (E8) | `dump-cfg` вернул success без файла: проверьте права каталога обмена на сервере и свободное место |
| «Недостаточно места для файла …: свободно … в …» (E9) | проверка до скачивания большого файла: освободите место или выберите другой каталог |
| «Расширение загружено под именем из файла: «Z» (запрошено «X»)…» (E11, предупреждение) | `load-cfg` берёт имя из файла, а после применения расширение переименовывается: «X» в базе больше нет, цель проекта `cfe/X` указывает на несуществующее расширение. Это предупреждение, не отказ |
| «После загрузки/применения расширения «X» его нет среди применённых расширений базы…» (E12) | сверка списком после применения: осталась заглушка или имени нет. Проверьте базу в Конфигураторе |
| «…обработано в базе, но проверить результат по списку расширений не удалось…» | команда прошла, сам список не прочитался; предупреждение, результат не подтверждён |
| «Агент конфигуратора перестал отвечать на команду «…» за отведённый срок…» | короткая команда (список расширений) не ответила за 30 с. Свой локальный агент остановлен и запустится со следующей операцией - повторите её; для удалённого - перезапустите агента на сервере (`1cv8 /AgentMode`), повтор команды автоматически не делается |
| «Расширение «X» загружено, но не применено» в итоге пакетной загрузки / перечень применённых расширений | пакетная загрузка остановилась на первом сбое; в сообщении названо, какие расширения уже применены, итоговая сверка - `verificationWarnings` |
| «Unable to open shell» при втором соединении | агент держит одну shell-сессию; дождитесь завершения первой операции |
| после разрыва соединения или простоя > 10 минут первая операция хранилища дольше обычной | PowerShell-сессия закрыта сервером по простою; хост открывает новую сессию сам (безопасные запросы повторяются один раз), `run` не повторяется — просто запустите операцию снова |

## 7. Известные ограничения

- Пароль ИБ в командной строке 1cv8 на сервере (`/P…`) виден в списке процессов сервера — как и локально.
- Ключ хоста SSH не проверяется (закрывается до слияния в `main`).
- После дельта-импорта `ConfigDumpInfo.xml` в проекте устаревает (его обновляют только полный архивный импорт и
  локальный режим); пакетный режим этот файл не использует.
- Расширение отслеживает только `*.xml`, `*.bsl` и `Template.*`: правки картинок, справки и других бинарных
  файлов выгрузки не откатываются импортом и не передаются частичной загрузкой.
- Если при ЗАГРУЗКЕ на сервере нет зеркала выгрузки, расширение строит его выгрузкой на сервере
  (`prepareMirror: full-dump`); правки базы, внесённые в обход расширения до этого момента, не попадут в
  проект инкрементальным импортом (Н56). Обход — удалить файл цели из `.v8vscedit/agent-sync/`: по коду
  следующий импорт станет архивным (полным), а следующая загрузка — полной, без базовой линии
  (`no-baseline`). На стенде не проверено.
- Два окна VS Code на одном проекте не координируются между собой блокировкой.
- Архив выгрузки больше 4 ГБ на ЗАПИСЬ (полная загрузка в обход зеркала) не поддерживается; чтение любого размера работает.
- Распознавание ручной замены выгрузки — по отпечатку `ConfigDumpInfo.xml`: при совпадении размера и времени изменения замена не ловится. Сироты уровня подобъекта не ищутся.
- После посева из проекта (в т. ч. после ручной замены) ручные правки проекта, не загруженные в базу, не попадут в загрузку «по изменениям» до полной загрузки — см. диалог посева.
- Вопрос о полной выгрузке задаётся только на импорте; на загрузке (P → БД) пока нет.
- После сбоя первого импорта серверная выгрузка повторяется заново (не кэшируется).
- CF/CFE через агента: сверка списком не отличает «применено» от «не изменилось» у существующего расширения;
  выгрузить неприменённую заглушку нельзя (E3); после применения расширение получает имя из файла (E11).
- Стендом не проверены: `dump-cfg` на ГБ (время, виден ли частичный файл), `load-cfg` при подключённых
  пользователях (монопольный режим), старая платформа (`CommandFormatError`).
- Подробно — [architecture.md](./architecture.md#известные-ограничения).

## 8. Чек-лист пилота на стенде

Часть поведения удалённой ветки тестами не исполняется (нет настоящего сервера 1С и WinRM) и проверяется
только на стенде. Проверяйте по порядку; результат каждого пункта — в журнал и в план
([plans/remote-designer-plan.md](./plans/remote-designer-plan.md), блок «Пилот Э9» и бэклог).

**Подключение и агент**

1. «Проверить подключение к серверу 1С» — все пять частей `[OK]`. Проверить обе ветки: агент запущен до и
   после старта VS Code.
2. Ключ хоста SSH: сохраняет ли агент ключ между перезапусками (`/AgentSSHHostKeyAuto` против
   `/AgentSSHHostKey`) — нужно для TOFU-проверки (Н50, обязательный гейт до слияния в `main`).
3. SFTP агента: `stat` пути, у которого в середине лежит файл, отвечает «нет файла» или ошибкой (Н34);
   не заменяет ли `rename` существующий КАТАЛОГ (Н35).
4. Первый импорт конфигурации > 65 535 файлов: прочитать архив, выданный самой платформой (`dump --archive`,
   zip64 от 1С), нашим распаковщиком (Н46); замер времени и памяти.
5а. Удаление объекта в базе → импорт: вопрос «Полная выгрузка на сервере» / «Выгружу вручную»; отказ ничего не меняет в проекте; ручная выгрузка поверх очищенной `src/cf` → следующий импорт предлагает посев, сирот нет.
5б. Массовая правка (больше 300, меньше 20000 файлов) идёт дельтой по SFTP без полной выгрузки; замер времени и числа одновременных SFTP-запросов (пулы STAT/LIST, бэклог плана).
5. Первый импорт БП КОРП (≈104 тыс. файлов): процесс расширения не падает по памяти («Array buffer
   allocation failed» не воспроизводится, пик памяти не растёт вместе с размером архива); на сервере ровно
   ОДНА выгрузка; вариант «Использовать выгрузку проекта» (файл версий проекта старше изменений в базе) —
   скачиваются только изменённые объекты; в журнале виден прогресс скачивания архива (каждые 10%);
   отмена посреди скачивания — «операция отменена», не ошибка; следующий импорт после посева — дельта.
6. Цикл «загрузить → обновить базу → загрузить» на реальной базе: `connect-ib` один раз, дельта-импорт
   после правки в базе скачивает только изменённое.

**CF/CFE и расширения через агента (Э28-Э31)**

24. Форма ответа `properties get` при ОДНОМ расширении (одиночное `extension-properties` без `success`) через
    реальный ssh2 на сервере: список из одного элемента, без ожидания срока 30 с; то же при 0 и 2+ расширениях.
25. `dump-cfg` на ГБ: время, виден ли частичный файл на сервере во время выгрузки, пик памяти; staging на клиенте
    и проверка свободного места до скачивания.
26. `load-cfg` при подключённых пользователях (клиент-серверная база): нужен ли монопольный режим, текст отказа.
27. Перезапуск СВОЕГО локального агента по сроку короткой команды (30 с): процесс остановлен, следующая операция
    запускает новый; для удалённого - понятная просьба перезапустить.
28. Старая платформа: распознавание `CommandFormatError` (E13) и понятность сообщения.

**PowerShell-сессия и хранилище (пилот Э9)**

7. Аутентификация PSSession: `Default` / `Negotiate`, подключение по IP, `useSsl` и нестандартный порт. При
   НЕВЕРНОМ пароле — сколько неудачных входов фиксирует контроллер домена за одну операцию (ожидается ровно
   один), какой `ErrorCode` у отказа (скрипт считает отказом аутентификации 5, 1326, 1909, 1311; HRESULT-формы
   `0x8007052E`, `0x8009030C` пока не распознаются — Н69); заблокированная учётка, недоступный контроллер
   домена.
8. `Copy-Item -FromSession` выгрузки `.cf` 100+ МБ: время, память, отсутствие обрыва по квотам WinRM.
9. Хранилище по UNC-пути (двойной прыжок Kerberos: сессия → общий ресурс) и по `tcp://`.
10. `1cv8 DESIGNER` в WinRM-сессии без рабочего стола: запускается ли, не ждёт ли диалогов, пишет ли `/Out`.
11. Отмена операции пользователем: дерево процессов на сервере убито (`taskkill /T /F`). Убитый
    `powershell.exe` клиента во время `run`: живёт ли 1cv8 на сервере и сколько (IdleTimeout 10 мин, Н61).
12. Разрыв сети/WinRM посреди операции и после простоя > 10 мин: `mktemp` проходит повтором на новом
    процессе, `run` — штатный отказ; понятность сообщения.
13. Кириллица в путях и аргументах; большой лог `/Out` (сотни КБ) без искажений.
14. Нагрузка опроса `run` (раз в 250 мс через `Invoke-Command`) на сервер и сеть за долгую операцию.
15. Лог `/ConfigurationRepositoryLock` снят (Э14, файловые базы): «Объект получен из хранилища: …» и «Объект
    захвачен для редактирования: …»; осталось сверить вид имён по всем видам объектов и захват корня
    конфигурации на стенде.
16. Удалённая операция хранилища сразу после `disconnect-ib` агента: база действительно свободна для 1cv8
    на сервере.
17. Передача `-ArgumentList` с `$null`-элементами (`resolveV8` по версии платформы) в реальной удалённой
    сессии (Н58).
18. Э14 на стенде: захват объекта, изменённого в хранилище, — «получен» в логе, проект после захвата
    догоняет базу (импорт в той же секции замка); вопрос при незагруженных правках проекта.
19. Э15: пакетная операция хранилища через удалённый исполнитель и сразу агентский импорт на клиент-серверной
    базе (1cDev) — сколько повторов `connect-ib` потребовалось (сообщение «База занята… повторяю»); если
    доходит до окна 15 с — пересмотреть окно.
20. `remote.v8Path` на `1cestart.exe` — проверка подключения даёт `v8-starter`, операция хранилища не стартует.
21. Э23 на клиент-серверной базе (БП): после `dump --update --force` mtime переписанных файлов зеркала по
    SFTP ≥ mtime метки `exchange/<op>.marker`, остальные файлы старше метки; строка «Изменено в
    зеркале: X из Y» соответствует числу реально изменённых объектов; при расхождении (растяжка) в журнале
    причина отката на полное сравнение. На локальном агенте допущение подтверждено.
22. Кнопка «Отмена» импорта: во время скачивания и во время `--update` — остановка, проект не тронут,
    после отмены на изменённом зеркале журнал предупреждает, следующий импорт идёт через посев.
23. Э26/Э27 на стенде (БП КОРП): получение из хранилища — `.cf` поставщика НЕ скачивается, журнал показывает
    «Конфигурация поставщика не изменилась…», вес, МБ/с и ETA; при ОБНОВЛЕНИИ поставщика (изменился
    `ParentConfigurations.bin`) `.cf` скачивается, а в строке «Части корня в списке изменений: …» видно, какие
    части корня назвал агент; полноценная проверка шлюза возможна только здесь (пакетно базу на поддержку
    не поставить). Заодно: пик памяти процесса не растёт вместе с размером большого файла.
